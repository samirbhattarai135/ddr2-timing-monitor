DDR2 Timing Monitor

DRAMPyML writes the JEDEC DDR2 rules as a timed Petri net. This project turns that net into VHDL tables. A small generic monitor runs the tables on a DDR2 command bus. It flags each command that the net rejects. No DDR2 rule is written by hand.

Vivado 2024.2 places and routes the monitor for the Nexys A7-100T part, with 0 errors. The estimated Fmax is 76 MHz. The DDR2 clock on the board is 325 MHz, so the monitor is too slow for the bus at this time. Nothing has run on a board. Section 9 gives the numbers.

One net, two ways to run it

The upstream net is the source of truth. A generator writes the net as VHDL tables. The monitor reads the tables. A Python oracle runs the same net on random traces. The testbench makes the monitor run each trace and compares every verdict. Select a box for its job.

2 · The net

Places, transitions and five arc kinds

A place holds tokens. A transition is one DDR2 command. Each bank has an ACTIVE place. The rank has PDN, SREF and SREF_FLAG. A pool of four tokens, NAW_Pool, models tFAW. CMD_BUS allows one command in each cycle. The upstream net has 12 commands: ACT, RD, WR, RDA, WRA and PRE for each bank, and PREA, REF, PDE, PDX, SRE and SRX for the rank.

The figure shows bank 0 of the net in build/ddr2_800/net_pkg.vhd. Arc kinds and counts come from drampyml/components/petri_net.py and the generated tables.

3 · The monitor, live

Issue commands to two banks

Choose a config. Set how many cycles to wait. Then press a command. The page runs the monitor rules and shows the verdict, the blocking arcs and the earliest legal cycle. The table has the real bounds from the generated net_pkg.vhd. It has 2 banks, 5 commands and 88 of the arcs. Power-down and self-refresh arcs are left out.

4 · Firing order and pipeline

Check, age, fire. The verdict comes one cycle later

Each cycle at most one command arrives as a transition id. The monitor does three steps in one clock edge. A legal command changes the state. An illegal command only counts as a violation.

Pipeline

The second command (B) is legal or illegal. The first (A) is legal.

Signal names are from rtl/petri_monitor.vhd and rtl/ddr2_bus_monitor.vhd. first_arc is the lowest-numbered blocking arc. Arc names are in build/<config>/arcs.tsv.

5 · Pin decoder

From CKE, CS#, RAS#, CAS#, WE#, A10 and BA to a transition id

The decoder follows Table 37 of the Micron datasheet. It samples the pins on each clock. It keeps the last value of CKE. It also keeps a flag that says whether the part is in self refresh. This flag tells SRX from PDX. Set the pins, or select a command to set them.

The page uses the same rules as the process in rtl/ddr2_cmd_decode.vhd. Transition ids are those of T_ID in build/ddr2_800/net_pkg.vhd. tb/tb_decode.vhd makes 60 checks on the real decoder: the 6 bank commands on each of the 8 banks, the 6 rank commands, NOP and DESELECT silent, LOAD MODE and a command on a CKE edge flagged.

6 · Results

The RTL agrees with the net on every command

Each config ran 200 random traces of 150 commands. A trace is a random walk on the net. Some steps are probes one cycle early, which must be illegal. Some steps are random noise. 7 · Where the numbers in the net come from

The shared timing values are DDR3-1600 values

DRAMPyML's DDR2 timing file and the DRAMSys MICRON_1Gb_DDR3-1600_8bit_G.json memspec share 16 parameters. 15 match by name. The 16th is tPD, which the table compares with DRAMSys CKE. All 16 are equal. 14 of them differ from the DRAMSys DDR2-800 file. The self-refresh and power-down exit values (tXSNR 2, tXSRD 200, tXARD 2) do not come from the DDR3 file. Its XS is 96 and its XSDLL is 512. They look like DDR2 cycle counts. The net also has 2 banks, but a 1 Gb DDR2 part has 8. The project adds a config with datasheet timing, ddr2_800. Select a row to compare the columns.

All values are in tCK cycles. DRAMSys values are from commit b43b4da of the memspec files. Source: tools/audit.py and tools/net.py. tRC is 22 in this repo (55 ns, Table 12) and 23 in DRAMSys (57.5 ns, the IDD table). With 2 banks, the four-activate window cannot bind: four ACT commands need two to the same bank, and tRC (38) is longer than tFAW (24).

8 · Audit

Nine places where the model and the datasheet disagree

Each row is a short command sequence. The net gives its verdict. The Micron 1Gb DDR2 datasheet (Rev. Y) gives the other. tools/audit.py fails if one row stops disagreeing, so an upstream fix shows at once. The ddr2_800 rows use datasheet timing, so they test the structure of the net, not its numbers. Load a row in the monitor of section 3 to see the model verdict.

Rows 1 and 2 come from the same line, CommandTimingConstraint(intra_rank, [ACT], [PRE], p.tRAS). It ties PRE on one bank to ACT on any bank. No rule ties PREA to ACT. Row 1 waits for tRCD on bank 1, so that Table 39 (bank n row-active, command to bank m) covers it. Rows 6 and 7 come from the model that lists both tXARD and tXARDS for every exit, so the larger bound always wins.

The Model column is the result of tools/audit.py, with the blocking arcs where it lists them. Row 2 rests on tRAS being the ACTIVATE-to-PRECHARGE period, which the model already applies to PRE. The datasheet has no sentence that says PREA must wait tRAS.

9 · Status and limits

What the monitor does not do

below target

Fmax

Estimated 76.1 MHz at a 3.077 ns target (WNS −10.055 ns) and 78.2 MHz at 2.5 ns (WNS −10.280 ns). The board DDR2 clock is 325 MHz.

Vivado 2024.2, out of context. Fmax = 1000 / (period − WNS). Both runs fail their target, so the values are estimates. Source: results/synth_vivado2024.2_2026-11-23.txt.

measured

Area

4,407 LUTs (6.95%) and 2,002 flip-flops (1.58%) at 3.077 ns. The monitor uses no block RAM and no DSP.

Part xc7a100tcsg324-1. The 2.5 ns run uses 4,413 LUTs.

pending

Board

Nothing has run on a board. The monitor must first run at one command for each DDR2 clock. The target part for the target board is the Nexys A7-100T (xc7a100tcsg324-1).

AreaIn this project
RulesThe monitor checks what the net checks. The net has only lower bounds. A missing refresh (tREFI) or a row open past tRAS(max) is not flagged.
ScopeSingle rank, AL = 0, burst length 8.
LOAD MODEOutside the net. The decoder sets unmodelled. The monitor ignores it.
AddressesThe decoder reads CKE, CS#, RAS#, CAS#, WE#, A10 and BA. It does not check row or column addresses.
Pin pattern H H LThe decoder gives no command and no flag for it (the burst terminate pattern).
Power-down exitThe mode (MR12) is not tracked, because the net does not tell fast and slow exit apart.
DatasheetThe monitor copies the 9 disagreements of section 8. It checks the net, not the datasheet.
Illegal commandThe monitor flags it and ignores it. The net cannot fire a disabled transition, so both sides stay in step.
